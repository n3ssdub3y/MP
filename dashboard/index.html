How the three agents are updated

MAPPO updates all three actors at once from the same batch. Each one assumes its teammates' policies stay fixed, so their changes can collide. HAPPO draws a random order each iteration and updates the agents one after another. Each agent's advantage is re-weighted by the factor M, which carries the policy changes its predecessors just made.

Correction factor M explorer

Drag the probability ratios r = πnew/πold of the first two agents in the order. M is what the third agent's advantage gets multiplied by.

stock HAPPO: M ← M · r clipped variant: M ← clip(M · r, 1 − ε, 1 + ε) (slide 12)

The clipped update is the modification described on slide 12. The happo.py / runner code in this repository is the stock HARL version; confirm the team's diff before presenting it. No ablation of this change was run, so the dashboard shows only its mechanics, not a measured effect.
